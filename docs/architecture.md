# 아키텍처

민원똑딱이 입력 한 줄을 민원서 초안으로 바꾸는 과정, 모듈 사이에 주고받는 데이터, 실패 시 동작을 정리한 문서.

## 모듈

| 모듈 | 역할 | 진입점 |
| --- | --- | --- |
| `complaint_draft/` | Streamlit 화면, 단계별 대화 흐름, 민원서 작성 | `streamlit run complaint_draft/app.py` |
| `complaint_agent/` | 이해 모듈과 근거 엔진을 잇는 `Agent`, 터미널 실행, 정답 세트 평가 | `python -m complaint_agent "..."` |
| `dialect_normalizer/` | 제주어 이해, 구조화, 되묻기 질문, Claude 호출 통로 | `python dialect_normalizer/structure.py "..."` |
| `evidence_engine/` | 데이터 적재, 검색, 지표 계산, 규칙 판정, 근거 패키지 | `python evidence_engine/run_engine.py --query q.json` |

- 이해 모듈과 근거 엔진은 JSON 두 개(구조화 질의, 근거 패키지)로만 연결됨
- 스키마 위치: `evidence_engine/contracts/`
- 엔진은 입력과 출력을 모두 이 스키마로 검사함

## 대화 흐름

- 흐름은 `complaint_draft/flow.py` 하나에 있음
- 화면(`app.py`)과 터미널(`complaint_agent/conversation.py`)이 같은 흐름을 호출함
- `flow.py`는 Streamlit에 의존하지 않는 순수 함수라서 다른 화면에서도 그대로 사용 가능

| 단계 | 하는 일 | 부르는 `Agent` 메서드 |
| --- | --- | --- |
| 불편 쓰기 | 글, 고른 지역과 주제 받기 | `understand(text, topics=...)`, `answer(r, emd_names=...)` |
| 되묻기 | 비어 있거나 불확실한 것만 하나씩 질문 | `answer(...)` |
| 뜻 고르기 | 주장마다 계산 가능한 뜻, 자료 없는 뜻, 기타를 보여 주고 최대 3개 선택 | `choose(query, interpretation, picks)` |
| 최종 확인 | 지역, 주제, 유형, 문제, 바라는 점을 보여 주고 확인. "아니요"면 처음 이해부터 다시 | `summary(query, places)` |
| 근거 고르기 | 엔진 결과를 카드로 보여 주고 넣을 근거 선택 | `evidence(query, places)` |
| 민원서 | 가린 질의와 근거 패키지로 초안 작성 | `handoff(result, query, package)` |

되묻기 규칙:

- 제주어: 사전 근거 없이 바꾼 낱말만 뜻을 질문함
  - 표준어로도 자주 쓰는 낱말(막, 확 등)은 묻지 않음
  - 같은 질문은 한 문장으로 묶음
- 읍면동: 문장에서 못 찾으면 시와 읍면동으로 묶은 목록에서 선택하게 함
  - "종달리"처럼 리 이름만 말하면 법정동 연계표로 읍면동을 찾음
- 주장: 불편한 점이 문장에서 안 나오면 더 자세히 질문함
  - 주제를 골랐다면 그 주제로 대신 채움
- 바라는 점: 선택 질문이라 건너뛰기 가능
- 기간: 묻지 않음
  - 증감 지표가 원자료의 최근 24개월로 정해져 있어서 기간을 받아도 계산이 바뀌지 않기 때문

같은 뜻의 주장이 여러 개에서 나오면 한 번만 넣음(`choose`가 지표 id로 중복을 거름).

## 근거 엔진

엔진은 두 방식을 섞어서 근거를 찾음.

- 온톨로지(B): 주장의 낱말을 개념으로 바꾸고, `ontology/jeju.ttl`의 관계를 3단계까지 따라가 관련 데이터를 찾음
  - 이렇게 찾은 근거에는 경로(`relation_path`)가 남음
- 카탈로그 검색(A): 데이터셋 카드를 BM25로 검색하고, 개념 태그와 공간, 최신성으로 순위를 매김
- `use_ontology=false`이면 B를 건너뛰고 A만으로 같은 형식의 결과를 냄

처리 순서:

1. 읍면동 이름을 행정동 코드로 바꿈
2. 온톨로지 개념 확장과 카탈로그 검색, 두 결과를 합쳐 순위 매김
3. `indicators/registry.yaml`에서 지표 선택
4. 읽기 전용 SQL로 계산하고 같은 유형 지역(읍면끼리, 동끼리)과 비교
5. 규칙 판정, 교차 확인 지표 붙이기, 차트
6. 출력 스키마 검증

### 판정 규칙

| 판정 | 화면 표기 | 뜻 |
| --- | --- | --- |
| `supported` | 자료로 확인됨 | 지표가 주장 방향으로 뚜렷함 |
| `partial` | 일부만 확인됨 | 중간 수준이거나, 대리 지표 또는 일부만 담은 자료로 판정함 |
| `contradicted` | 자료와 다름 | 지표가 주장과 반대 방향임 |
| `unverifiable` | 자료로 확인 불가 | 맞는 지표나 데이터가 없음. 빈칸(`gaps`)에 사유를 남김 |

판정을 낮추는 경우:

- 대리 지표: 주장이 말하는 측면(운행 횟수, 이용 실적, 거리, 시설 수, 위험)과 지표가 재는 측면이 다르면 `supported`를 `partial`로 낮춤
  - "간접 근거"로 표시함
- 약한 자료: CCTV 목록처럼 공개 목록이 일부만 담은 자료는 `supported`와 `contradicted`를 `partial`로 낮춤
- 교차 확인: 판정한 지표 옆에 인구 증감률, 65세 이상 비율, 인구 밀도 같은 맥락 값을 "함께 볼 자료"로 붙임
  - 판정 자체는 바꾸지 않음
- 범용 틀: 등록 지표가 없는 "부족하다", "멀다" 주장은 미리 받은 시설 목록으로 인구 1만 명당 개수를 세어 "참고용 자동 집계"로 보여 줌
  - 판정은 "일부만 확인됨"까지만 냄

## 민원서 작성

`complaint_draft/draft.py`의 `build_draft`가 근거 패키지로 초안을 만듦.

1. Claude(`writer.py`)가 제목, 민원 내용, 요청 사항을 합니다체로 작성
   - 근거는 이름만 넘기고 숫자는 넘기지 않음
2. 코드가 결과를 검사함
   - 숫자는 사용자 글, 고른 주장, 지역 이름에 있는 것만 허용
   - 빈 칸이 없어야 함
   - 제목에는 장소가 들어가고 45자를 넘지 않아야 함
   - 개인정보를 한 번 더 가림
3. 검사를 통과하지 못하거나 Claude를 쓸 수 없으면 `templates.py`의 기본 문장 틀로 만들고 화면에 알림
4. 근거 자료 칸은 엔진의 값과 출처를 그대로 옮김
   - 사용자가 고쳐 쓸 수 없게 잠겨 있음

- 제출용 글은 국민신문고 칸에 맞춰 제목과 내용 두 덩어리로 만듦
- 글자 수 제한(제목 200자, 내용 40,000자)을 화면에 표시함

## 실패 처리

| 상황 | 동작 | 화면 안내 |
| --- | --- | --- |
| Claude 사용 불가 (스위치 꺼짐, 키 없음, 네트워크나 API 오류) | 규칙 구조화: 문장 속 읍면동 이름과 리 이름, 엔진 주제 단서로 유형을 정하고 주장은 문장 하나로 둠 | "AI 이해 단계를 쓰지 못해 규칙으로 정리" |
| 민원서 다듬기 실패 | 기본 문장 틀로 만듦 | "문장을 자동으로 다듬지 못해" |
| 제주어 사전이나 예문 색인 없음 | 표준어 변환 없이 구조화함 | 개발 모드에서만 표시 |
| 근거 DB 없음 | 엔진 mock (형식만, 계산값이 아님), 복사와 인쇄 차단 | "근거 DB가 없어 근거 수치는 형식 예시로만" |
| 프로그램 시작 실패 | 원인별로 안내 (DB를 다른 창이 쓰는 중, 자료가 없음 등) | "대화 기능을 준비하지 못했어요" |

- Claude 응답은 최대 60초 대기, 재시도는 한 번만 함
- 첫 화면을 띄울 때 사전, 색인, 근거 엔진을 미리 불러 두어서 첫 요청도 바로 처리됨

## 주고받는 데이터

### 구조화 질의 (이해 모듈 → 엔진, `query.schema.json`)

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `request_id` | 예 | 요청 고유값 |
| `normalized_text` | 예 | 표준어로 바꾼 문장 |
| `complaint_type` | 예 | `교통`, `의료 접근`, `환경·청소`, `안전·재난`, `복지`, `생활물가`, `기타` 중 하나 |
| `claims` | 예 | `{id, text, indicator_id?}` 목록. `indicator_id`는 뜻 고르기에서 고른 지표 |
| `location.emd_name` | 예 | 읍면동 이름. 엔진이 행정동 코드로 바꿈 |
| `location.emd_code` | 아니요 | 행정동 8자리 코드 (예: 구좌읍 `50110256`) |
| `period` | 아니요 | `{from, to}`, `YYYY-MM` |
| `targets`, `user_request` | 아니요 | 대상 낱말, 바라는 점 |
| `raw_text` | 아니요 | 원문. 엔진은 받자마자 버림 |

### 뜻 선택지 (엔진 → 이해 모듈, `interpretation.schema.json`)

- 주장마다 `options[]`가 옴
- `kind` 값
  - `indicator`: 계산 가능
  - `no_data`: 그 뜻을 확인할 자료가 없는 뜻
  - `other`: 기타
- 맨 앞이 추천, 맨 끝은 항상 기타
- 선택지 문장은 지표 등록부의 틀로만 만들어서 민원 원문이 옮겨지지 않음

### 근거 패키지 (엔진 → 이해 모듈, `evidence.schema.json`)

- `engine`: `hybrid`, `catalog`, `mock`
- `evidence[]`: 주장 id, 판정, 지표, 값, 단위, 지역 비교, 출처, 기준일, 찾은 방식, 관계 경로, 주의 사항
- `gaps[]`: 데이터가 없어 판정하지 못한 개념과 사유

### 민원서로 넘기는 것 (`handoff`)

- `query`: 가린 구조화 질의, 원문 제외
- `package`: 근거 패키지
- `places`: 고른 지역
- `structured_by`: `llm` 또는 `rules`
- `notices`: 실패 기록
- `pii_masked`: 가린 종류
